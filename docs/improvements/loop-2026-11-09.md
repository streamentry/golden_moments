# Loop run 2026-11-09: line height finding, change measured and not shipped

Purpose: the same 4-hour loop prompt as [loop-2026-11-08.md](loop-2026-11-08.md). This run searched for sources the ledger has not used, picked one idea, and tried it. The idea was a real gap, but the change breaks five layout tests, so it is not in the code. This log records the measured result and the decision needed.

## Searched

Standard search and one page fetch. Snippets are not evidence on their own; only the W3C page was read in full.

1. **W3C, Understanding SC 1.4.12 Text Spacing** (read in full): <https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html>. Users must be able to set line height to at least 1.5 times the font size with no loss of content or function.
2. **NIA, "Making Your Website Senior Friendly"** (catalog entry and a secondary summary only; the NIA page itself was not opened): <https://www.nia.nih.gov/health/publication/making-your-website-senior-friendly>. Its checklist, as quoted by secondary sources, asks for 1.5 or double line spacing and 12 to 14 point type.
3. **Alzheimer Society of Canada, written communication tip sheet** (search snippet only): italics and all capitals are hard to read; avoid cursive fonts; use plain backgrounds without patterns. Source: <https://admin.alzheimer.ca/sites/default/files/documents/DFC-Writtten%20Comm%20Tip%20sheet_Final.pdf>.
4. **Alzheimer's Society, Dementia Digital Design Guidelines** (named by search results, not opened): the Society's own page was not reachable here, and the spreadsheet copy in results has unclear provenance. Nothing below relies on it.

These are new families for the ledger. Rounds 1 to 38 covered contrast, touch, focus, audio, print, and navigation. Typography was checked only as "sans serif" (G3) and "Larger text" (G4).

## What was tried

1. **Red test.** Added `reading text is set at 1.5 line height or more (WCAG 1.4.12)` to `test/design_system_test.dart`. It failed with the value 1.4, as expected.
2. **Change.** Set `body-lg`, `body-md` and `body-sm` to 1.5 in `DESIGN.md` and `lib/design_system.dart` together. The design-system test file then passed all 64 tests, and `dart format` reported no changes.
3. **Full suite.** `flutter test` (Flutter 3.47.7, the version pinned in `.fvmrc`) had five failures. The same three files pass at the base commit (41 tests), so the change caused them:

| File | Test | Failure |
| --- | --- | --- |
| `test/features/gentle_activities/picture_puzzle_test.dart` | tap-to-place completes the puzzle; finishing is calm | Piece tap lands on the bottom bar at y 706 of 844 and does not hit the piece. |
| `picture_puzzle_test.dart` | a wrong placement is not flagged and can be taken back | Same cause. |
| `picture_puzzle_test.dart` | Start again begins a new puzzle without asking | Same cause. |
| `test/features/gentle_activities/photo_together_test.dart` | after Next or Hide the new picture is back in view | "The picture is together." is not found. |
| `test/features/gentle_activities/photo_collection_journey_test.dart` | at 200% text on a small phone the problem and the way forward are the first thing on screen | "Show my photos" is not found among hit-testable widgets. |

4. **Revert.** All three files were restored with `git checkout`. The branch has no code change from this run.

## What the failures mean

The five tests are the app's existing 200% text and layout guards. At 1.4 line height they pass, but with little room. A user who sets 1.5 line height, which WCAG 1.4.12 says must be possible without losing content, would lose visible controls on the puzzle, Photo Together, and the photo collection's first screen. So the finding matters more than the token change: the layouts are fragile at the spacing that the cited source and the WCAG criterion treat as a floor.

## Result

No application or website code changed in this run. The branch contains this log, the README and TRACKING rows, and a correction to the audit row for line height. The check was run on the change and is not left as a failing test.
