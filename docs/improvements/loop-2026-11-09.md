# Loop run 2026-11-09: reading text at 1.5 line height, with layout fixes

Purpose: the same 4-hour loop prompt as [loop-2026-11-08.md](loop-2026-11-08.md). This run searched for sources the ledger has not used, picked one idea, and implemented it. The idea needed three layout fixes to keep the existing 200%-text tests passing.

## Searched

Standard search and one page fetch. Snippets are not evidence on their own; only the W3C page was read in full.

1. **W3C, Understanding SC 1.4.12 Text Spacing** (read in full): <https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html>. Users must be able to set line height to at least 1.5 times the font size with no loss of content or function.
2. **NIA, "Making Your Website Senior Friendly"** (catalog entry and a secondary summary only; the NIA page itself was not opened): <https://www.nia.nih.gov/health/publication/making-your-website-senior-friendly>. Its checklist, as quoted by secondary sources, asks for 1.5 or double line spacing and 12 to 14 point type.
3. **Alzheimer Society of Canada, written communication tip sheet** (search snippet only): italics and all capitals are hard to read; avoid cursive fonts; use plain backgrounds without patterns. Source: <https://admin.alzheimer.ca/sites/default/files/documents/DFC-Writtten%20Comm%20Tip%20sheet_Final.pdf>.
4. **Alzheimer's Society, Dementia Digital Design Guidelines** (named by search results, not opened): the Society's own page was not reachable here, and the spreadsheet copy in results has unclear provenance. Nothing below relies on it.

These are new families for the ledger. Rounds 1 to 38 covered contrast, touch, focus, audio, print, and navigation.

## What changed

1. **Tokens.** `body-lg`, `body-md` and `body-sm` set to 1.5 in `DESIGN.md` and `lib/design_system.dart` together. Headings keep their tokens.
2. **Test.** `reading text is set at 1.5 line height or more (WCAG 1.4.12)` in `test/design_system_test.dart`. It failed at 1.4 before the change.
3. **Picture Puzzle** (`lib/features/gentle_activities/presentation/picture_puzzle_page.dart`). The board is sized to 36% of the body height, down from 42%. At 1.5 the instructions and the reference row grew, and the pieces tray fell under the bottom bar (y 706 of 844 at 390 by 844). Now the tray is in view on a phone with no scrolling.
4. **Photo Together** (`lib/features/gentle_activities/presentation/photo_together_page.dart`). The status note after Hide or Next (for example "Hidden for this visit.") is body-md, not body-lg. At 200% on a 320 by 568 phone, the note was about 240 pixels tall and pushed the new picture out of the list's visible area. The picture's top now sits 16 pixels inside the list's bottom edge.
5. **Photo collection recovery** (`lib/features/gentle_activities/presentation/photo_collection_page.dart`). The problem text is body-md, not body-lg. At 200% on a 320 by 568 phone, the "Show my photos" button was pushed off the first screen.

- `flutter test` (Flutter 3.47.7, pinned in `.fvmrc`): **686 of 686 pass**. Before this change, the five tests in the three files below failed; all pass now. The file set is picture_puzzle, photo_together, and photo_collection_journey. The earlier 41-test base run of those files also passes.
- `flutter analyze --fatal-infos --fatal-warnings`: no issues.
- `dart format --set-exit-if-changed lib test`: no changes.
- `design.md lint DESIGN.md` (`@google/design.md@0.4.0`, installed in the scratchpad): 0 errors, 0 warnings, 1 info (the token summary, which is not a finding).
- Visual check: temporary widget-test renders with the shipped fonts, then deleted. Icons do not load in those renders, so icon glyphs show as boxes. What they show:
  - 390 by 844 at 1.0: the Picture Puzzle screen is correct. Instructions, the whole-picture reference, the board, the pieces tray and the two exit buttons are all on screen.
  - 320 by 568 at 2.0 (Picture Puzzle): the instructions and the board are below the fold, and the stacked exit buttons take most of the screen. The content still scrolls, so nothing is lost. This was true before the change too.
  - 320 by 568 at 2.0 (Photo Together): Next is visible; Previous is partly under the bottom bar. It scrolls.

## Result and what is still weak

- No content is lost at 1.5 line height: every check above either fits on screen or scrolls to it. This is the condition WCAG 1.4.12 sets.
- The Photo Together result after Hide is weak. The picture is in view, but only its top 16 pixels show above the bottom edge of the list at 200% on a small phone. A real fix would move the status note below the picture, or make the note shorter. That is a UX decision, so it is not made here.
- The Picture Puzzle screen at 200% on a small phone is long, and the board starts below the fold. This is pre-existing and was not changed.
