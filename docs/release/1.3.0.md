# 1.3.0+5 release checklist

Candidate only. This repository change does not publish an app or upload store metadata. Main is not automatically release-approved.

## Automated validation

```sh
flutter pub get
flutter analyze
flutter test --coverage
flutter test test/features/gentle_activities --reporter expanded
python -m unittest discover -s tests -v
python scripts/release_metadata.py --check
```

Resolve and commit the lockfile after the new picker dependency. Do not hand-invent checksums. Keep the existing full workflow; focused checks are additional, not a replacement. Record baseline failures separately from regressions. Before submission run `python scripts/release_metadata.py --release`; pending evidence must fail.

## Device and upgrade gates

Step-by-step scenarios, expected results and the evidence format are in [device-acceptance.md](device-acceptance.md).

- Signed iOS archive succeeds for the intended distribution target; bundle IDs/signing remain unchanged. Check actual build-number availability before upload.
- Fresh iPhone/iPad install starts a four-tile activity in airplane mode without preexisting content.
- Test photo selection, cancel, limited access, HEIC, iCloud-only originals, duplicate selection, one remaining slot, capacity, low storage, deletion and restart. Originals remain unchanged.
- Test Android process destruction while the picker is open and recovery confirmation.
- Upgrade from the previous release without losing downloaded packs/preferences. Optional library navigation, sound and downloads still behave correctly.
- VoiceOver/TalkBack, 200% text scale, narrow screens, landscape, iPad, contrast and tap targets pass manual review.
- Five-caregiver comprehension review; none infer diagnosis or treatment.

## Privacy and store gates

Audit the native build for Firebase/other SDK behavior, persisted collection settings, unexpected network calls and permissions. Static findings, the CI guard and the remaining native/runtime steps are recorded in [network-privacy-audit.md](network-privacy-audit.md); that review is not the native audit. Update the privacy policy and App Privacy form to match actual behavior. Device backups may include photo copies; do not promise they never leave hardware.

Verify advertising declarations, age rating, country availability, pricing and language support. Do not reuse historical non-English medical/brain-training claims. No fabricated testimonials. A disease-targeted title requires review of overall intended use; a disclaimer is not legal clearance.

Capture genuine approved iPhone/iPad screenshots, record file paths in metadata, and attach build/device evidence to `docs/specs/release-status.json`. Export verified copy into App Store Connect manually. No upload, sale, campaign or public release is authorized by the validation script.

## Recovery

Before release keep a baseline build and preserve old data identifiers. If the new flow is faulty, route home back to the library without deleting the local-photo directory. Never reset a collection to hide corruption. Investigate and repair using a separate reviewed change.
